# 보안

## Principal과 scope

Keystone session과 API key는 `Principal`로 정규화된다. 두 credential 모두 현재 enabled user/project와 현재 Keystone role-ID inference DAG로 해석한 service authority를 요구한다. Project membership은 `role_assignments.list(user=user_id, project=project_id, effective=True)`의 해당 project row로 확인하며 group/inherited grant를 유지한다. Verified system admin 예외를 제외하면 이 membership이 필요하고, 일반 사용자는 정확한 전역 service leaf가 필요하다. Token role snapshot이나 caller role header, `lumen_user|editor|admin` 이름 자체는 권한이 아니다. Graph 누락·cycle·알 수 없는 ID·builtin 이름의 domain/global 충돌은 fail-closed이며 current authority lookup 장애는 503이다. Native `member`가 없으면 write leaf는 사용할 수 없고 native `reader`는 service reader leaf만 허용한다. 비검증 project/domain `admin|manager`는 service 권한을 주지 않는다.

Global admin은 `role_assignments.list(user=user_id, system="all")`로 **`effective=True` 없이 direct system assignment**를 읽는다. Keystone effective expansion은 direct system grant를 누락하기 때문이다. `scope.system.all is True`인 row만 선택하고, 그 role ID를 현재 검증된 DAG로 확장하여 정확한 unique global `admin` ID에 도달할 때만 system admin이다. 이름 비교나 고정 parent expansion으로 대체하지 않으며 project/domain admin은 승격하지 않는다. `_is_system_admin` 조회 실패는 `False`로 닫히고, current project authority resolver의 directory/graph 실패는 503이다. System 조회 수정은 project effective membership·enabled owner/project 검사·API-key attenuation을 완화하지 않는다.

API key는 한 project에 묶이며 `source="api"`, `is_system_admin=false`다. Owner의 verified system authority는 tenant service action에만 적용하고 global admin identity를 key에 부여하지 않는다. Key 발급과 `issuance-policy`는 `lumen-keys_editor`와 requested scope 전체의 fresh current owner subset을 요구하고 사용 시에는 issuer leaf를 유지할 필요가 없다. 저장된 scope는 current owner 권한을 넓히지 못한다. Ordinary nullable expiry는 이름·scope·quota와 원자 저장하며 미래 aware 시간만 허용한다. `X-Project-Id`가 다르면 403이고 malformed, unknown, empty-effective-scope, revoked/expired key는 401이다. Local seed도 실제 owner ID와 directory-read credential을 요구하며 예전 owned key 회전은 `native:keys:delete`를 검사한다.

하나의 요청에 `X-API-Key`, `Authorization`, `X-Auth-Token` credential을 둘 이상 보내면 400으로 거절한다. 예외는 하나다: 동일한 API key를 `X-API-Key`와 `Authorization: Bearer`로 함께 보내는 경우(Claude Code의 기본 동작)만 `hmac.compare_digest` 비교 후 허용한다. `/v1/api-keys`와 owner limits는 Keystone-only keys-editor, revoke는 resources-admin이다. `/v1/admin/*`는 verified system admin 전용이다. Agent/workspace/code/Git route도 이제 각각 service action과 ownership을 요구하며 scoped ordinary key를 인증 타입만으로 우회시키지 않는다. Agent/skill/plugin inventory는 기본 private instructions/config를 제외하고 `include_private=true`에 editor를 요구한다. Asset upload/config는 assets-editor, asset/file/extension/agent 삭제는 resources-admin, history/memory 수정·삭제는 history-editor로 분리한다. MCP 설정/OAuth start는 mcp-editor이며 start는 Keystone-only; browser-bound callback owner도 code exchange 전에 재검증한다.

Legacy Lumen device gateway는 ordinary API key와 별도 custom device authorization 경계다. Public device endpoint는 client secret을 받지 않고 정확한 fixed scope만 허용하며 Redis rate-limit failure를 503으로 거부한다. Human user code와 device code는 SHA-256 hash만 MariaDB에 저장한다. Afterglow의 authenticated approval이 current Keystone user/project를 grant에 묶고, poll은 approved grant를 한 번만 consume하여 `credential_kind="claude_gateway"` key를 발급한다. Gateway route는 credential kind와 fixed scope를 모두 검사하므로 일반 API key는 사용할 수 없다. 발급 key는 hash만 저장되고 24시간 뒤 즉시 인증 실패한다. 이 경계는 current Claude Apps Gateway `/login` 호환성을 주장하지 않는다.

## Execution credential domains

Lumen의 tenant authority는 caller 또는 journal에 기록한 **원래 owner user/project**의 현재 enabled grants와 native capability graph다. Directory 조회용 `_get_admin_ks_client`는 configured service project의 credential로 user/project/role graph를 읽을 뿐 tenant 실행 credential이 아니다. 사용하지 않던 `get_admin_connection_for_project`는 제거했다. 서비스 password를 caller-selected tenant로 rescope하는 factory나 tenant `member` role assignment를 제공하지 않는다.

Verified system admin의 `X-Target-Project-Id`는 기존 logical target 계약을 유지한다. `get_os_conn`은 validated effective caller token과 **원래 `connection_project_id`**로 연결하며 logical target을 service-password 연결로 바꾸지 않는다. API key는 system-admin owner가 발급해도 tenant-bound attenuation이고 foreign project/target header는 거부한다.

Paid provider inference/billing secret과 operator가 자체 API/worker/sandbox infrastructure를 운영하는 Nova application credential은 별도 domain이다. Tenant Trust나 사용자 service leaf를 이 secret의 대체물로 사용하지 않는다. Operator cloud profile/secret은 public caller가 선택하거나 journal owner/project에서 만들어내는 credential이 아니다. Owner 권한 재검증은 provider/tool 호출 **허가**이고, provider secret 또는 controller의 own-service credential은 그 허가를 대신하지 않는다.

Nova/Zun의 공유 `cloud_connection`은 explicit application-credential ID/secret으로 `Connection(cloud=None)`을 사용한다. Installed openstacksdk 3.3.0은 이 경로에서 YAML/env loading을 비활성화하므로 `OS_CLOUD`, `OS_PROJECT_*`, ambient clouds.yaml은 credential·tenant scope를 대체하지 않는다. Profile `project_id`는 operator resource bookkeeping이며 auth payload의 scope selector가 아니다(application credential 자체의 project binding을 사용). Credential 선택은 compliant하여 유지했다. Follow-up real-SDK 검증이 발견한 Session constructor의 tuple timeout TypeError만 scalar `api_timeout=15`로 수정했으며, 실제 request의 `(5, 15)` connect/read timeout과 retry=0 wrapper는 그대로다. `tests/test_runtime_scaling.py::test_cloud_connection_real_sdk_ignores_ambient_auth_and_scope`는 meaningful ambient positive control 뒤에 operator auth method/payload의 scope 부재, credential, TLS/region/timeout/typed retry accessor를 검사한다. Real cloud/provider는 호출하지 않는다.

Initial implementation evidence: source-reviewed and behavioral regressions test-defined, with no mid-flight checks. `tests/test_native_keystone_authority.py`는 installed Keystone/OpenStack SDK와 synthetic directory HTTP로 current owner capability loss 및 system-admin logical target/original connection scope를 검사한다. Authorized follow-up verification receipts는 parent에게 별도 보고하며, real cloud/provider 호출 또는 production 수용을 뜻하지 않는다.

`tests/system/test_service_role_authority.py::test_system_admin_target_key_cannot_substitute_tenant_scope`는 real API HTTP에서 system-admin human의 logical target에 발급한 key도 foreign `X-Project-Id`/`X-Target-Project-Id`를 거부하는 consumer contract를 정의한다. Installed-SDK current-owner regression은 chat/images/audio/tools leaf 제거 뒤에도 privileged directory identity가 owner 대신 실행 권한을 줄 수 없음을 검사한다. Durable/native/Batch/compaction/title/memory/tool gate의 실제 source map은 local OpenSpec design에 기록했다; 이미 compliant한 authority나 completed-checkpoint settlement를 재작성하지 않았다.

## Media WebSocket trust boundary

이미지, 음성 생성·전사, realtime은 kind별 scoped API key 또는 Keystone principal과 user/project ownership을 검사한다. 이미지 편집·전사는 canonical S3 asset의 소유권과 scanner 결과를 확인하며 임의 URL, file path, unchecked MIME을 provider 입력으로 사용하지 않는다. Realtime provider는 지원되는 공식 OpenAI/Gemini HTTPS WebSocket origin, API-key credential, model ID allowlist 및 양방향 정확한 가격을 요구한다. Custom API base와 subscription token은 허용하지 않는다. 브라우저는 Afterglow의 기존 Keystone 인증 BFF에서만 60초 단일 소비 ticket을 얻으며 Lumen connect token·provider key는 browser response에서 제거한다. BFF WS는 허용 origin과 atomic ticket consume 뒤 internal Lumen endpoint로 헤더 token을 전달한다. Native Lumen WS도 원본 browser Origin의 CORS allowlist를 검증한다. Query ticket/token을 쓰는 환경에서는 proxy access log의 query 필드를 마스킹한다. **Gemini 공식 upstream Live WS는 서버에서 `?key=` query로 인증하므로 provider URI·handshake 예외·debug trace도 로그/APM에서 기록하지 않는다**(OpenAI upstream은 Bearer header).

마이크 PCM16·provider output·realtime 자막은 Afterglow/Lumen DB, S3, 로그, journal에 남기지 않는다. 계산된 바이트·초와 청구 구성 요소만 encrypted run segment/usage ledger에 기록한다. 오디오는 provider로 전송되므로 provider 측 보존/학습 정책은 별도 확인한다. Browser UI의 자막/오디오 버퍼는 session close/logout/project switch에 지운다. Frame 크기 64 KiB, decoded PCM 32 KiB, provider 직접 연결 시간·idle·전체 세션 길이를 제한하고 WS disconnect/취소 시에도 측정된 사용량을 정산한다. Provider I/O 이후 결과가 불확실하면 재시도하지 않고 reservation `unknown`을 유지한다.
공유 메시지 그래프는 owner `user_id`/`project_id`를 갖고 각 conversation은 별도의 owner-bound mapping과 `chat_conversation_messages` 도달 가능성 집합을 갖는다. Conversation-bound message/history/fork/retry/context 경로는 요청자의 conversation 소유권, graph 소유권, 메시지 graph 일치와 **그 conversation의 membership**을 검사한다. `chat_messages.conversation_id`는 작성 당시의 nullable origin 정보이며 권한 검사의 대체재가 아니다. 같은 graph에 존재하는 source-only sibling도 fork의 membership이 없으면 조회/leaf 선택할 수 없다. 별도의 run/event 조회는 run의 user/project 소유권, asset download는 `ChatAsset.user_id/project_id` 소유권을 검사하며 둘 다 message view membership의 대체 경로가 아니다. 원본 conversation을 삭제하더라도 살아 있는 mapping만 접근 가능하며, 마지막 mapping 삭제는 graph/message/asset-link를 정리한다. Provider run/usage ledger는 보존 정책과 origin 감사 경계를 유지하고 공유 메시지를 근거로 fork 소유 run처럼 노출하지 않는다.

## 관리자 plugin과 agent 권한

설치된 Python wheel은 API/worker process 안에서 실행되는 **trusted operator code**이지 사용자 코드 sandbox가 아니다. `[lumen.plugin_config]`/`PLUGIN_CONFIG`는 선택한 entry point의 distribution 이름과 정확한 버전을 import **이전**에 확인하고 manifest/API version/configuration schema/host capability를 검증한다. 선택한 plugin이 없거나 검증에 실패하면 API/worker 시작이 실패하며 fallback하지 않는다. Wheel 배포/allowlist 변경은 운영자의 이미지 배포 권한이다; native `/v1/plugin-bindings`는 이미 승인된 tool/skill export의 설정 인스턴스일 뿐 설치 권한이 아니다. Admin binding과 `GET /v1/admin/plugins`는 Keystone 관리자 전용, user binding은 `native:extensions:read|write|delete` (reader/config-editor/destructive resources-admin 분리)와 export의 `user_configurable`/owner scope가 적용된다. Binding config에는 평문 secret 대신 서버 측 secret reference를 사용하고 revoke/config 변경은 실행 직전 재인가를 거친다.

`plan`/`code` 및 `delegate_agent`는 protocol v2 + PostgreSQL checkpointer + 명시적 `agent_budget`/project cap을 전제로 한다. 기본 project quota의 0은 무제한이 아니라 비활성이다. 자식은 parent project/user의 승인된 agent/정책/모델·도구 snapshot 안에서만 생성되며 credit/child slot/sandbox slot/seconds를 원자적으로 예약한다. `read` child는 process effect가 없고 parent account memory/prompt를 통째로 상속하지 않는다. `GET /v1/runs/{id}/children`은 같은 user/project의 소유 run 및 `native:runs:read`를 요구한다. API key의 `execution_mode=plan|code`는 허용하지 않지만 agent inventory/config는 해당 current leaf와 stored read/write scope, 삭제는 destructive admin scope로 검사한다.

## Secret과 암호화

`lumen_encryption_key`는 정확히 64 hex characters여야 한다. AES-GCM/HKDF domain separation으로 chat content, inference provider key, provider billing administrator key를 각각 분리한다. Billing administrator key는 direct OpenAI/Anthropic 조직 보고서 조회에만 사용하고 모델 inference에는 전달하지 않는다. key/credential/provider secret은 API response, journal snapshot, log에 노출하지 않는다. Ordinary/Gateway API key는 SHA-256 hash만 저장하고 issuance response에서만 plaintext를 준다. Device/user code도 원문 대신 hash만 저장한다. provider projection은 billing key 값 대신 `has_billing_admin_key`만 반환한다. public/admin API key 조회 및 한도 프로젝션에서는 secret 및 hash가 제외되며 모든 한도/사용량 숫자는 고정소수점 문자열 또는 `null`로만 노출된다.

`OPENAI_API_KEY`/`GEMINI_API_KEY`로 초기화한 provider는 비밀 값이 아닌 `api_key_env` **변수 이름만** DB에 기록한다. Bootstrap은 DB에 저장된 관리자 key, 다른 env binding 또는 provider 정책을 교체하지 않는다. API/worker 모두 같은 변수를 받아야 하며 일부 process에만 제공되면 readiness와 실제 실행 결과가 달라질 수 있다. 로컬 `.env`는 Git에서 제외하고 mode `0600`, `.dockerignore`로 build context에서도 제외한다. 배포 key는 제한된 secret inventory/store로 전달한다. Compose의 전체 resolved config, Docker container inspection, Ansible task output, shell history/APM/log에 provider secret이 노출되지 않게 접근·출력 권한을 제한한다. 환경 변수 제거는 이미 저장된 encrypted DB key를 무효화하지 않으므로 회전·폐기는 두 credential source를 각각 확인한다.

## Network boundary

Custom HTTP tool은 SSRF/DNS pinning transport, private/internal address block, redirect 미추적, bounded body를 사용한다. MCP는 HTTPS HTTP transport만 허용하며 OAuth callback은 initiator cookie/PKCE browser flow를 쓴다. TLS 검증은 기본 활성이다. `insecure=true` 또는 host allowlist를 완화하기 전에는 deployment network policy와 CA path를 검토한다.

### Generic remote MCP와 run-scoped Kubernetes tools

Remote MCP publication은 owner consent가 아니며 browser/unknown effect는 v2 `external_mutation` 승인 경계다(v1은 explicit read만). Caller header나 connector credential은 승인 authority가 아니며 current owner/config/activation/credential epoch 재검증을 우회하지 못한다. Remote Afterglow의 scoped credential·frozen auth·approval 경계도 유지한다. Generic authenticated connector 계약은 원격 browser/session 격리를 보장하지 않는다; remote 서비스의 실제 capability·보존·격리는 별도 검토 대상이다.

Playwright/filesystem의 관리형 실행 경로는 run-scoped Kubernetes sandbox다. Enabled pool의 digest-pinned image와 pinned manifest가 승인된 stdio MCP command/schema/effect를 정의한다. Durable worker의 run lease owner/fence, controller가 발급한 run/resource generation/call-fingerprint capability, identity-pinned mTLS와 sandbox의 실행 journal이 dispatch를 제한한다. Tool result가 indeterminate이면 성공으로 표시하거나 자동 재실행하지 않는다. Terminal/cancel/descendant 회수는 기존 durable resource release intent와 controller의 exact owned-resource lifecycle을 따른다.

격리 주장은 실제 RuntimeClass(`runsc`/`kata`), Pod Security·RBAC·CNI default-deny/egress·resource 한도 및 operator qualification에 근거해야 한다. Pod에 cluster token·controller signing key를 전달하지 않는다. 과거 permanent gateway/broker·named OCI diagnostic receipt는 현재 Kubernetes 경로의 배포 권한이나 qualification이 아니다. [현재 수용 상태](testing.md#run-scoped-kubernetes-tool-cutover-acceptance-pending)의 native approval/resume·run 격리·회수·양 architecture runtime·production gate는 pending이며 image build/import·readiness로 대신하지 않는다.


Gateway public base는 정확히 origin + `/v1/claude-gateway`여야 하며 loopback development 외에는 HTTPS만 허용한다. Host gate는 metadata/device/token/inference route에도 적용한다. Verification URI는 Afterglow public shell이고 approval은 authenticated BFF에서만 가능하다. Query user code는 session storage에 정규화한 뒤 URL에서 제거하며 referrer/cache를 차단한다.

Managed controller는 public API와 별도 HTTPS listener에서 CA-검증된 내부 통신을 수신한다. 초기 bootstrap은 10분짜리 한 번 쓰는 token의 hash만 저장하며 CSR의 사설키를 받지 않고 resource role/id/generation에 묶인 인증서를 서명한다. 일반 dispatch에는 verified client certificate identity와 짧은 수명의 run/resource/generation/lease-fence/call-fingerprint capability가 필요하다. Operator dispatch key, cloud application credential, Kubernetes bearer token, CA private key와 controller listener/probe private key는 controller에만 보관하고 API/sandbox/worker에는 전달하지 않는다. `managed_networks` CIDR, Nova cloud project 분리, image/ownership labels, provider·guest preflight는 서로 독립된 경계다; public `/v1/health`, image build, API-side feature gate만으로 isolation이 증명되지는 않는다. Sandbox runtime의 host/guest 요구사항 및 deadline/indeterminate journal 계약은 [sandbox 이미지 계약](../packages/lumen-sandbox/IMAGE.md)을 따른다.

고정 worker는 public CA와 전용 `tls.worker_client_cert_file`/`tls.worker_client_key_file`을 받는다. `tls.operator_client_*`은 controller-to-guest readiness probe 전용이며 worker에 재사용하지 않는다. `fixed_workers`의 `{id, certificate_fingerprint}` pin은 내부 CA가 발급한 유효한 non-CA `clientAuth` leaf의 단일 URI SAN `spiffe://lumen/fixed-worker/<id>`와 결합된다. 이 identity는 live fixed-worker registration의 own run/lease fence에 대한 dispatch를 허용할 뿐 cluster credential·dispatch signing key·controller probe authority가 아니다. Worker host secret directory는 controller directory와 분리한다. Enabled Kubernetes pool의 pinned tool manifest는 같은 상대경로의 read-only worker 사본이 필요하지만 controller-only Kubernetes CA/token/qualification은 worker mount에 넣지 않는다. 구체적인 mount/field 계약은 [운영 가이드](operations.md#managed-cloud-runtime-선택과-기동)를 따른다.

Kolla에서 `lumen_runtime_enabled: true`와 `enable_lumen_worker: true`를 함께 사용하면 sandbox dispatch 여부와 무관하게 전용 `tls.worker_client_cert_file`/`tls.worker_client_key_file` pair와 비어 있지 않은 `fixed_workers`가 필수이며, 누락은 `runtime_worker_identity` precheck 실패다. Controller-only provider credential이나 operator probe identity를 대신 worker에 전달해 이 gate를 우회하지 않는다.

Kubernetes sandbox의 operator prerequisite는 **`lumen-service`의 Drover-managed cluster**다. Drover 경로의 cluster/node lifecycle과 namespace·RuntimeClass·runtime/CNI 설치·operator qualification은 Lumen/Ansible의 소유 범위가 아니다. Lumen controller는 미리 준비한 namespace 안에서 own on-demand sandbox Pod·일회용 bootstrap Secret·per-resource NetworkPolicy·NodePort Service의 lifecycle만 소유한다. Service는 해당 Pod UID에 결합하고 Pod 부재가 확인된 뒤에만 owned Service·Secret·NetworkPolicy를 정리한다. Pool은 `role=sandbox`, `min_replicas=0`, 유한한 양수 `max_replicas`, immutable `@sha256` image와 명시적 `runtime_class_name`/`runtime_class_handler`(`runsc` 또는 `kata[-…]`)를 요구한다. Namespace의 Pod Security `restricted`, 전체 Pod ingress/egress default deny, namespace-scoped least-privilege RBAC 및 실제 runtime/CNI network qualification은 서로 대체할 수 없다. Pod에는 cluster service-account token을 automount하지 않으며 bootstrap Secret에는 one-use token과 controller public CA만 넣는다.

Controller와 fixed/managed worker host는 Pod가 실행되는 **node IP(`status.hostIP`)의 할당된 NodePort**에 접근해야 한다. 방화벽·routing은 해당 source host→node IP의 cluster TCP NodePort 범위(기본 `30000–32767`, 설정 변경 시 실제 범위)를 허용하고 `managed_networks`에는 대상 node IP들을 포함한다. Service의 `externalTrafficPolicy: Local`은 원래 source IP를 보존하여 Pod TCP8013의 `controller_ingress_cidrs` policy가 controller/worker의 실제 exact host CIDR(`/32` 또는 `/128`)을 검사하게 한다. NodePort는 public 접근 허가나 mTLS 대체 수단이 아니다. `bootstrap_egress_cidrs`도 exact host만 허용한다. `egress="none"`은 bootstrap 외 egress/DNS를 열지 않고 DNS 설정은 비어 있어야 한다. `egress="public"`은 **1–3개 explicit `dns_server_cidrs` exact host**를 요구하며 Pod의 `dnsPolicy: None`, explicit nameserver, `ndots: "1"`, 빈 search 목록으로 cluster/host DNS와 search suffix 상속을 막는다. Policy는 해당 DNS host의 UDP/TCP53과 private/metadata/cluster CIDR을 제외한 public TCP80/443만 허용한다. 추가 site 제외 범위는 `egress_deny_cidrs`(기본 `()`, 최대 64개 strict network CIDR, host bit가 설정된 network는 거부)에 명시하며 public TCP80/443 허용 대상에서 제외한다. 실제 CNI enforcement·source 보존·DNS·routing은 operator가 별도로 qualification해야 한다.

Controller는 enabled provider의 실제 `preflight(pool)` 성공 전 listener/reconciliation을 열지 않고 Kubernetes create 전에도 preflight를 다시 수행한다. Kubernetes gate는 namespace ownership·non-terminating 상태·`restricted`, RuntimeClass의 exact handler·UID/spec, digest-pinned qualification·tool manifest, pre-provisioned `lumen-default-deny` 및 나머지 policy의 exact ownership/spec, non-persisted `SelfSubjectRulesReview`를 확인한다. Namespace RBAC는 Pods·Services 각각 `get,list,create,delete`, Secrets `get,create,delete`, NetworkPolicies `get,list,create,delete`와 namespace/RuntimeClass `get`으로 제한한다. `authorization.k8s.io`의 `selfsubjectaccessreviews`·`selfsubjectrulesreviews`는 `create`만 허용하며, 추가 identity review 예외도 **정확히 `authentication.k8s.io`/`selfsubjectreviews`의 `create`만** 허용한다. Wildcard/namespace-admin·Secret list/watch·다른 resource/verb grant와 incomplete RBAC review는 거부한다. 이 namespace review는 다른 namespace/cluster의 grant를 발견하지 못하므로 cluster-wide scope는 operator provisioning/qualification 책임이다. Qualification은 server/namespace UID/RuntimeClass UID·spec/cluster CIDRs/pool digest와 runtime/CNI probe SHA-256·유한한 measured PID bound를 결합해야 한다. `egress_deny_cidrs`를 생략해도 기본 `model_dump(mode="json")`에는 `egress_deny_cidrs: []`가 포함되므로 기존 Kubernetes `pool_digest`와 pinned qualification은 바뀐다; custom digest override나 기본값 제외로 이를 숨기지 않는다. Cutover 전에 기존 resource를 drain·정리하고 새 pool digest·실제 evidence에 맞춰 qualification과 파일 hash pin을 재생성한다. 새 provider identity와 `auxiliary-uids`에는 Service UID도 결합되며 이전 compact identity는 거부되므로 기존 resource의 자동 호환/adoption을 가정하지 않는다. 파일 hash·API object·권한 조회는 runtime/CNI가 실제 격리를 강제했다는 live 증거를 만들어내지 않는다. 이 문서는 설정/운영 gate를 기록하며 Drover 배포, Kubernetes 연결, sandbox 실행 또는 production isolation 수용을 주장하지 않는다.

Worker의 private guest HTTPS transport는 **동일 TLS socket**에서 CA, resource URI SAN, 허용된 generation fingerprint 집합을 먼저 검증한 뒤에만 bearer capability 또는 source를 전송한다. Controller capability endpoint는 별도의 hostname-verifying TLS context를 사용한다. Managed worker registration/heartbeat와 controller grant는 resource generation과 current 또는 아직 유효한 previous pin을 다시 비교한다. Renewal activation은 current/pending/previous와 registration fingerprint를 원자 갱신한다. Pending pin은 activation 외에는 허용하지 않고 previous는 overlap 종료 뒤 거부한다. 단, 이미 발급된 단일 method/path/fence/call 범위 capability는 run lease 취소 직후에도 최장 15초 만료 전까지 sandbox에서 수락될 수 있다. Sandbox는 네트워크 격리상 live MariaDB lease를 재조회하지 않으며 새 fence 관측 전까지 이 짧은 revocation window가 남는다. 즉각적인 물리적 중단을 요구하는 운영 정책에는 sandbox 강제 삭제/acknowledged revocation 구현이 추가로 필요하며, 현재 상태를 즉시 revoke 가능한 격리로 주장하지 않는다.

Trusted guest config는 mTLS owner resource/generation, 동결한 profile ID/digest, root-owned regular 0600 config의 SHA-256을 확인한 뒤 allowlisted service config/secret만 반환한다. Bootstrap token은 root-only로 교환 후 제거한다. Root supervisor가 versioned root:appuser 0750/0440 identity와 `/run/lumen` config를 관리하고 service child는 appuser로 실행한다. Service group의 certificate key read 권한은 해당 trusted service의 내부 호출을 위한 것이며 사용자 코드 sandbox와 공유하지 않는다. Root supervisor/container에는 host Docker socket을 전달하지 않는다.

API private drain은 operator certificate fingerprint allowlist·resource/generation·monotonic persisted fence로 제한한다. Child drain은 loopback address와 per-boot token을 모두 검사한다. Renewal은 child 재시작 없이 새 연결의 identity를 교체하되 기존 TLS 연결을 유지한다. Leaf/CA 만료나 갱신 복구 실패는 fail-closed이며 expired certificate를 허용하지 않는다. Guest-config, renewal, drain endpoint는 공개 ingress에 노출하지 않는다.


## Durable trust boundary

Admission은 principal action과 project ownership을 검사하고 immutable request/model/extension snapshot을 journal에 저장한다. Chat, generated images/audio, tool execution은 독립 leaf다. Plain chat는 history-editor를 요구하지 않는다. Memory 조회는 history-reader, 명시적 저장/삭제는 history-editor이며 자동 추출은 새 generation/history 권한을 검사한다. Client tool schemas, stored tools/MCP, plugin/skill/agent, provider search 및 intrinsic search 모델도 tools-user를 요구한다. Key scope가 넓어도 현재 owner leaf가 없으면 403이다.

Direct API 및 worker는 **새 provider/tool I/O 직전** 현재 owner/project membership·role graph와 key active/revoke/expiry·owner·stored scopes를 다시 검사한다. Online text/media, realtime, Batch, title/summary/memory auxiliary 경로에 적용하며 issuer keys-editor 유지는 요구하지 않는다. Denied optional memory/title work는 완료된 chat를 바꾸지 않는다. 이미 commit한 provider-start intent의 결과 회수나 완료 checkpoint replay/정산을 retroactive하게 거절하거나 재호출하지 않는다. Directory outage는 stale 권한으로 fallback하지 않는다. Cancellation은 먼저 owned run을 찾고 image/audio/realtime/text의 matching primary operation만 요구한다; source asset/editor/tool 권한을 cancel에 재요구하지 않는다. Foreign owner는 404이며 반복 media cancel은 동일한 persisted terminal descriptor를 반환한다.

Remote global MCP publication은 owner 실행 consent가 아니다. `chat_mcp_activations`의 authenticated user/project/config version과 현재 server activation, OAuth 서버의 matching connected encrypted token을 함께 검사한다. Configuration 변경은 재승인해야 하고 activation generation을 frozen fingerprint에 묶어 disable/re-enable가 이전 대기 승인을 되살리지 않는다. 선택된 다른 사용자·프로젝트의 activation은 사용할 수 없으며 API key에 global-admin opt-in을 주지 않는다. Direct user MCP의 기존 소유권·SSRF·secret boundary는 변하지 않는다.

2026-10-07 `lumen-rolegrades-20261006`의 실제 API/worker/MariaDB/Redis + TLS MinIO/ClamAV에서 HTTP authority smoke **16 passed**. Installed Keystone SDK는 synthetic directory HTTP를 조회했고 provider는 internal-network synthetic endpoint다. 요청 scope subset, current graph leaf 제거, native/compat 독립 text/image/audio/tools bounds, revoked key의 8 action/boundary denial, persistent media ownership/idempotence를 실행했다. Queued worker denial 2건은 HTTP-completed image의 frozen request를 offline-pool SQL fixture로 복사한 뒤 graph 제거 또는 key revoke 후 release한 증거다(두 번째 HTTP admission이 아님): worker registration과 failed journal, NULL provider start, reservation 0행, upstream count 불변을 확인했다. 이 증거는 real Keystone RBAC, paid provider, deployment 또는 cloud acceptance가 아니다.

Batch와 Files는 owner(project+user) 범위다. 형식이 틀린 ID나 다른 owner의 batch/file은 존재 여부를 드러내지 않고 404다. Native batch는 compat route에서 보이지 않는다. 새 `native:batches:*`, `compat:batches:*`, `compat:files:*` scope는 기본 발급 scope가 아니며, 생성 시 항목 operation/endpoint scope를 함께 요구한다. Batch body는 `headers`, `api_key`, `api_base`, `base_url`, credential·custom provider 같은 transport override와 임의 URL dispatch, `stream=true`를 거부한다. Item 요청/결과와 frozen payload는 chat content key로 암호화하며 idempotency key는 SHA-256 hash만 저장한다. 업로드는 parse 전 크기 제한과 0600 spool을 거쳐 ClamAV가 clean으로 판정한 뒤에만 private S3 object로 노출된다. Scan 실패·미완료 파일은 읽거나 Batch에 사용할 수 없다. 삭제·만료는 새 조회와 재사용을 즉시 막지만 실행 중 batch가 pin한 입력 object와 native 입력 asset은 batch가 끝날 때까지 물리 삭제하지 않는다.

Batch validation은 최대 100행 chunk마다 현재 owner authority와 key 상태·stored scope의 교집합을 한 번 조회해 각 행의 required scope를 검사한다. 행마다 directory를 다시 조회하지 않으므로 50,000행 파일이 Keystone 부하를 행 수만큼 늘리지 않는다. Materialization도 project/batch/item lock을 잡기 전에 같은 교집합을 한 번 조회하므로 directory latency가 lock 보유 시간을 늘리지 않는다. 이 조회들은 provider I/O 권한이 아니다. 각 provider I/O 직전의 per-run 재검증은 그대로이며, 조회 뒤 발생한 revoke나 downgrade는 그 시점에 거부된다.

사용자 월간 한도는 UTC 달력월 기준 immutable `ChatUsageLog.credited_cost` 원장을 모체로 사용한다. `user_wallets.max_quota_* IS NULL`은 시스템 정책 상속, 양수는 개인 override, `0`은 명시적 무제한이고, runtime `chat_quota_policies` singleton이 없을 때만 배포 설정 `chat_default_monthly_quota`를 기본 월 한도로 사용한다. 독립 주간 ceiling이 무제한이어도 월 admission 검사는 항상 먼저 수행되므로 월 한도를 우회하지 않는다. 유한 주간 override가 유한 월 한도보다 크면 409 Conflict다. API-key owner/admin ceiling은 이 사용자 유효 한도와 함께 요청 시점에 동적으로 계산한다. 일반 text completion의 precheck와 최종 ledger 사이에서는 동시/단일 요청 오버슈트가 가능하다. Media provider I/O 시작 전에는 wallet row lock으로 사용자·API key의 미정산 `reserved|unknown` bound까지 합산해 월/주 credit hold를 검사한다. 비용을 확정하지 못한 `unknown`은 월 rollover 후에도 hold를 유지하므로 운영자가 provider/ledger를 대조해야 한다. 이미 수락된 run과 동일 `Idempotency-Key` replay는 스냅샷 계약을 따른다. 당월 관리 뷰, historical usage surface, 관리자 사용자 상세 ledger는 서로 구별한다.

## 운영 점검

- encryption key와 MariaDB backup은 같은 recovery plan으로 보관한다.
- provider/MCP/Git secret은 secret manager에서 주입한다.
- logs와 alert payload에 Authorization, API key, tool argument, raw provider response를 넣지 않는다.
- provider billing 조회는 provider/capability별 고정된 공식 HTTPS endpoint만 사용하고 redirect를 따르지 않는다. OpenAI/Anthropic 관리자 키는 별도 crypto domain에서 복호화해 organization report 요청에만 쓰며 custom base로 보내지 않는다. 응답은 allowlist된 숫자·통화·상태 필드만 projection하며 Authorization, raw upstream body, 원문 오류를 반환하거나 기록하지 않는다.
- admin network 접근과 user-native API surface를 분리한다.
- runtime restore/scale-in에는 provider 소유권+generation과 worker drain/active lease를 대조한다. 미확정 cloud create를 새 VM으로 재시도하거나 중단된 provider/tool 작업을 증거 없이 중복 실행하지 않는다.
