# Lumen Architecture

## Overview

Lumen은 LiteLLM provider 실행, LangGraph/LangChain agent runtime, 대화·durable run journal, server-managed tool/skill/memory, usage ledger와 provider secret을 소유하는 독립 AI 채팅 서비스다. Afterglow는 제품 UI와 인증된 BFF를 소유하고, Lumen은 `/v1` API와 실제 실행·영속성을 소유한다.

- Repository: https://github.com/openstack-afterglow/lumen
- 분석 기준: `dev` branch, 현재 working tree source와 설정
- 버전: root `lumen` package `0.4.0` (`pyproject.toml`, `lumen/__init__.py`, `uv.lock`), 독립 `lumen-sdk` `0.2.1` (`sdk/pyproject.toml`), discovery/API contract `1.0.0` (`lumen/api/compat/discovery.py`). Kolla의 package-owned API/worker/controller image default는 `0.4.0` tag를 가리키지만 이번 후보 이미지 게시·운영 배포는 아직 검증하지 않았다. 앞선 `v0.3.1` package 및 네 이미지 tag workflow는 source `9eed5d170bc3fad3dae658e6119cb80e5831052e`에서 성공했고 multi-architecture manifest의 OCI revision을 확인했다. 이것은 Kolla 운영 설치·cloud acceptance가 아니다. `lumen_source_version`은 별도 source-build commit pin이다.
- 주요 실행 단위: FastAPI API(`lumen/main.py`), durable worker(`lumen/worker.py`), migration CLI(`lumen/scripts/migrate.py`), migration 이후 provider bootstrap CLI(`lumen/scripts/seed_providers.py`), 독립 `lumen-sdk`, 선택적 local Console(`lumen_console/`)

짧게 말하면 대부분의 HTTP route는 인증·scope·입력 검증과 journal 조회만 담당하고, `chat_admission`이 실행에 필요한 권한·context·provider/model·extension snapshot을 고정한다. `durable_runs`가 MariaDB transaction으로 intent/run/event를 기록하고, worker가 lease를 획득해 provider·tool을 실행한다. Redis는 일반 run wakeup 최적화지만 realtime 한 번 쓰는 connect ticket에는 필수다. Realtime 예외는 API WebSocket process가 직접 lease를 소유하며 양방향 provider audio를 relay/정산한다.

이 후보의 `lumen-api`, `lumen-worker`, `lumen-controller`, `lumen-test` OCI 이미지를 `linux/amd64`와 `linux/arm64`로 각각 빌드하고 로컬 Docker에 적재했다. 네 타깃의 두 architecture 컨테이너 모두에서 `lumen.main`·`lumen.worker`·`lumen.controller` import와 API route 164개가 확인됐고 `x86_64`/`aarch64`가 출력됐다. 이미지를 registry에 발행하거나 운영 worker/provider에 연결한 증거는 아니다.

Combined 0.4.0/source와 운영 중 shared graph 019 SQL을 통합한 2026-09-29 확인: `uv run lumen-test contract`는 service 1,451건(86 deselected), SDK 125건과 양쪽 Ruff를 통과했고, `uv run lumen-test integration`은 실제 MariaDB/Redis에서 77건을 통과했다. Media hold 간 경합과 다른 사용자의 text reservation insert를 `innodb_snapshot_isolation=OFF|ON` 양쪽에서 검증했다. 비교용으로 이전 `REPEATABLE READ` + 전체 예약 테이블 `FOR UPDATE`를 복원하면 text insert 시나리오는 양쪽 mode에서 timeout으로 실패한다. 최종 image/system/운영 smoke는 별도 gate이며 이 수치를 운영 배포의 증거로 보지 않는다.

최신 source 계약: direct Gemini/Anthropic exact LiteLLM catalog의 cache-read/5분 write/1시간 write `above_200k_tokens` 단가가 있으면 **단일 호출**의 provider-reported 총 prompt token이 200,000을 초과할 때만 해당 tier를 쓴다. 기본·고문맥 단가와 출처는 run/summary/advisor admission snapshot에 고정되며 수동 cache 가격이 우선한다. Advisor는 각 호출의 prompt 크기를 usage component에 동봉해 개별 tier로 정산한다. Frozen title job은 누락 입력/출력 가격에 public catalog를 적용하지 않는다. OpenAI virtual `lumen`의 cached tokens는 executor cache-read만 투영한다. Direct Anthropic의 자동 system breakpoint는 message뿐 아니라 명시적인 tool/request `cache_control`이 있는 경우에도 생략한다.

Subscription transport(`anthropic_subscription`)도 API-key 경로와 같이 `litellm.drop_params`를 켠 뒤 LiteLLM을 호출한다. 따라서 model이 거부하는 sampling 파라미터(예: `claude-opus-5-5`의 `temperature` ≠ 1, context compaction의 `temperature=0`)를 제거한다. `claude-opus-5-5`의 adaptive thinking/effort와 compat passthrough 제한은 `docs/operations.md`에 구분한다. Title 생성은 frozen route가 광고한 가장 낮은 effort만 선택하고 `acompletion`의 `extra`로 전달한다. 이전 top-level kwarg는 reasoning model에서 `TypeError`를 일으켰다. 테스트는 실제 wrapper를 거쳐 LiteLLM 경계의 요청을 확인하며 live provider 증거는 아니다.

한 provider 응답에 여러 native compaction iteration이 합산되고 iteration별 TTL split이 없으면 cache tier 판정도 그 합산 입력에 적용된다. 내부 호출별 가격과 동일하다는 증거가 아니며 organization invoice 대조가 필요하다.

플러그인 경계: `default-skills`는 DB skill ID가 선택된 경우에만 필요하며 다른 승인된 skills binding만 고른 요청은 해당 provider에서 resolve한다. Per-user custom HTTP는 기존 `/v1/custom-tools`의 선택/인가 경로를 유지하고 plugin catalogue export를 추가하지 않는다. Remote MCP snapshot은 provider-safe한 공개 tool 이름과 별도의 원래 RPC method를 묶어 dispatch에 재사용한다. 이는 기존 authority·MariaDB journal 및 API/worker 책임 분리를 바꾸지 않는다.

Ingress enable/create는 pool lease row lock을 외부 SDK write가 완료될 때까지 잡아 stale controller의 재활성화를 직렬화한다. 다만 Octavia가 변경을 반영한 뒤 SDK가 실패하면 member ID가 원장에 없을 수 있으므로 operator는 `lumen-<resource_id>` 이름으로 남은 member를 확인·disable/delete해야 한다. Nova/Octavia live rollout로 승격하지 않는다.

## Runtime flows

### Native durable admission and replay

1. `POST /v1/conversations/{conversation_id}/completions` 또는 `/v1/temp-completions`가 UUID `Idempotency-Key`, owner project, required scopes를 확인한다.
2. `prepare_context_input()`이 모델 capability, workspace/memory, agent/skill, extension selection, execution protocol과 tool schema를 계산한다. protocol v2는 encrypted PostgreSQL checkpointer 설정 없이는 admission되지 않는다.
3. `durable_runs.admission.create_persistent_run()` 또는 `create_temp_run()`이 idempotency fingerprint, active-run 및 revision fence를 잠근 뒤 user message, active-path append, `active_leaf_id`, encrypted request payload, run/provider rows, `run.started`/queued event를 하나의 MariaDB transaction으로 저장한다.
4. commit 이후 `wake_run()`이 `afterglow:chat:runs`에 ID를 넣는다. Redis가 없거나 publish가 유실되면 worker의 `queued_run_ids()` polling이 queued state를 발견한다.
5. worker가 run lease를 소유한 뒤 graph/engine을 호출한다. provider call, tool call, delta, usage, approval/interaction, terminal result를 journal에 기록한다. lease owner/expiry가 맞지 않으면 write를 중단하고 stale recovery가 재시도 또는 fail-closed한다.
6. `GET /v1/runs/{run_id}/events`는 owner-scoped MariaDB journal을 cursor 이후 읽고, terminal event까지 polling SSE와 keepalive를 제공한다. HTTP request나 SSE 연결은 실행을 취소하거나 실행 lifetime을 소유하지 않는다.

Native Search는 `chat_admission`이 고정한 feature options를 `durable_runs.execution` → `engine.stream` → `graph.stream` → provider transport까지 전달한다. 저장된 capability override나 subscription credential은 실제 native 지원 범위를 늘릴 수 없고 capability는 검색 실행 증거가 아니다. Perplexity legacy Sonar는 Chat Completions `web_search_options`를 유지하고, Agent Responses의 non-Sonar native opt-in은 hosted `web_search` tool을 function tools와 함께 보낸다. Agent Sonar에는 중복 hosted tool을 보내지 않는다. Lumen의 자동 `strict=true`는 지원하는 recursively closed schema에만 적용하며, compatibility client의 명시적 strict 선택과 선택적인 description/parameters는 보존한다. 서버 도구 실행은 strict 여부와 무관하게 JSON/schema를 검증하고 실패 시 dispatch하지 않는다. Provider-returned URL citations/search-result items만 canonical durable citation parts로 저장한다. Native 모델의 token 가격이 있어도 managed 검색의 별도 component 가격이 없으면 admission을 거부한다. Perplexity Agent Sonar와 legacy Sonar의 서로 다른 가격은 API base로 구분하고, exact Agent Sonar/GLM-5.3 공식 가격의 provenance를 admission snapshot과 관리자 model projection에 유지한다.

### Durable media and API-owned realtime

1. Admin은 migration 020의 `model_kind`·`media_pricing`에 route의 실제 단위를 설정한다. `providers.pricing`은 직접 연결 가능성·key·양쪽 realtime 가격을 검증하고 목록/capabilities에서 실행 가능한 voice·format만 공개한다. Subscription/custom base나 token-price fallback으로 media를 활성화하지 않는다.
2. Image 생성/편집 및 TTS/STT admission은 UUID idempotency와 user/project owner·scanned input asset을 검증해 encrypted request/route/pricing을 MariaDB에 고정한다. Worker claim 후 account wallet을 lock해 미정산 media holds와 사용자·API-key 월/주 상한을 검사하고 `ChatModelCallReservation`과 provider-started segment를 I/O 이전에 commit한다. Image/TTS 결과는 scanner/S3 소유 asset으로 고정되고 STT 텍스트는 encrypted segment에 남는다. Provider output과 frozen 단위 가격으로 한 번만 usage ledger를 정산한다.
3. Realtime admission은 최대 input/output PCM seconds를 snapshot과 bound로 기록하고 Redis에 digest-only 60초 ticket을 넣는다. API WS가 ticket을 atomic consume한 뒤 queued run을 fenced claim, wallet hold·provider-started segment를 commit하고 canonical OpenAI/Gemini upstream WSS에 서버 측 API key header로 접속한다. Native/compat wire는 64 KiB frame, PCM chunk·sample-rate·voice·duration·idle bound를 검사한다. Lumen DB에는 audio/transcript 원문 대신 input/output PCM bytes·초 및 ledger만 남는다. Disconnect/cancel은 측정된 초로 정산하며 미확정 provider result는 `unknown` hold로 유지한다. Worker queued polling은 realtime run을 제외한다.
4. Afterglow BFF는 Keystone session에서 browser 전용 60초 one-use ticket만 반환하고 Lumen connect token/provider key를 browser에 반환하지 않는다. Browser microphone worklet/PCM playback/transcript는 logout/project switch/session close에서 해제한다. Provider가 오디오를 처리하므로 browser 메모리 보관만 주장하지 않는다.

Reasoning effort는 admission에서 모델 capability로 검증해 run snapshot에 고정한다(`chat_admission._validated_reasoning_effort`). 명시 `none`은 omission으로 바꾸지 않고, models.dev capability가 끄기를 광고할 때만 허용한다. 광고 방식은 effort 목록의 `none`, `toggle`, `budget_tokens.min == 0` 중 하나이며, thinking이 opt-in인 `anthropic` provider도 허용한다. 그렇지 않으면 422다. 판정은 `capabilities.reasoning_can_be_disabled` 하나이며 `GET /v1/chat/models`가 같은 값을 `reasoning_none_supported`로 노출해 client가 규칙을 복제하지 않게 한다. LiteLLM 1.93은 `none`을 OpenAI gpt-5/o3에 그대로 전달하고 Gemini에는 `thinkingBudget: 0`으로 바꾸기 때문이다. 이를 위해 `models_dev._model_capabilities`는 `budget_tokens`의 정수 `min`/`max`를 저장하고, LiteLLM probe capability(`reasoning_options=[]`)는 끄기 미확인으로 본다. GPT-5 도구 호환성 검사는 이 판정 뒤에 실행되므로 `none`을 계속 허용하고, 거절 안내에는 모델이 지원할 때만 "없음"을 넣는다. 이 규칙은 unit/API test(`tests/test_chat_completions.py`, `tests/test_chat_models_dev.py`, `tests/test_chat_conversations.py`, `tests/test_ai_compat.py`)로만 확인했고 live provider에서는 확인하지 않았다. Title job은 별도 규칙(광고된 effort 목록의 가장 싼 값 또는 omission, 아래 title 문단)을 따른다. 요청 의도가 없는 운영자 기본값 `chat_reasoning_effort="none"`(stateless `completion_api` streaming 경로)은 같은 판정으로 끌 수 없는 모델에서 effort를 생략한다(omission). `graph.py`가 GPT-5 도구 요청에 붙이는 암묵적 `none`은 admission이 아니라 worker가 같은 판정을 frozen route에 적용해 결정한다(다음 문단).

GPT-5 도구 요청의 암묵적 `reasoning_effort="none"`은 run의 frozen capability로 결정한다. Worker는 `ps.resolve_model_snapshot`의 route에서 `capabilities.reasoning_can_be_disabled`를 계산해 `execution` → `engine.stream` → `graph.stream`으로 넘긴다(기본값 `False`). Graph는 OpenAI provider, `gpt-5*` 이름, effort `auto`/미지정, tool schema가 있고 이 값이 참일 때만 추측으로 `none`을 먼저 보낸다. Provider가 `none` 자체를 거부하면 이후 같은 frozen route는 기본값을 쓰고, 기본값의 tool+reasoning 충돌을 관측한 route는 이후 명시 `none`을 쓴다. 학습은 항상 `provider_failed` boundary 전에 수행한다. Durable hook은 `provider_result_unknown`으로 현재 run을 중단하며 같은 라운드 재시도는 abort하지 않는 hookless 경로에만 있다. 암묵 `none`의 일반 연결 오류는 disable 거부로 기록하지 않는다. Child run도 같은 worker 경로를 쓴다. 새 persisted payload·migration·저장소는 없으며 provider 오류 문구는 live에서 미확인이다.

0.3.1 통합에서는 세 reasoning memo (`_REASONING_UNSUPPORTED`, `_TOOL_REASONING_EXPLICIT_NONE`, `_TOOL_REASONING_NONE_REJECTED`)의 key를 model 이름 대신 worker가 resolve한 `config_version_hash`로 제한한다. `reasoning_route_key`를 `execution` → `engine` → `graph`로 전달하며, frozen identity가 없는 직접 호출은 process-wide memo를 읽거나 쓰지 않는다. 같은 이름의 다른 provider/model row나 새 configuration은 이전 route의 실패를 상속하지 않는다. 검증된 명시 `none`은 stale LiteLLM probe나 generic fallback memo 때문에 생략하지 않으며, 실패를 provider-default reasoning 재시도로 바꾸지 않는다. 회귀 테스트는 다른 route/version, identity 부재와 명시 disable 보존을 정의하지만 이번 작업에서 실행하지 않았다.

Opaque OpenAI route의 명시 `none`은 `drop_params=True`인 LiteLLM의 generic whitelist에서도 유실되지 않도록 `allowed_openai_params`에 `reasoning_effort` 하나만 추가한다. 이 override는 OpenAI wire에만 적용하며 Anthropic/Gemini의 native parameter 변환을 덮어쓰지 않는다. Graph 회귀는 wrapper kwargs가 아니라 설치된 `get_optional_params` mapper의 결과를 검사한다(정의만 했으며 미실행).

0.4.0 후보에서 0.3.1 reasoning 수정과 media 경로를 합친 뒤 contract 1,448건·SDK 125건, 실제 MariaDB/Redis integration 43건, containerized API/worker system 9건을 통과했다. `lumen-api`, `lumen-worker`, `lumen-controller`, `lumen-sandbox` 각각 linux/amd64·linux/arm64 이미지를 빌드하고 두 플랫폼에서 실제 실행해 Python machine/version 및 sandbox Node v24.21.0을 확인했다. 이는 local build/runtime 증거이며 GHCR tag 게시·Kolla migration/배포 증거는 아니다.

### Plugin selection, managed resources and child joins

`lumen-plugin-api`는 실행 DTO/Protocol만 게시한다. 관리자 allowlist의 distribution/name/version이 실제 entry point와 일치해야 registry가 시작되고, host는 필요한 capability만 플러그인에 전달한다. Native 요청은 DB HTTP tool/skill/MCP와 별도의 UUID plugin binding을 owner-scope로 resolve하여 immutable identity/schema/config digest를 freeze한다. Worker는 실행·approval 경계에서 재인가하며 버전/권한 변경을 fail-closed한다. 다섯 wheel은 core ORM/private import 없이 독립 설치되는 신뢰된 서버 코드이며 사용자 코드 sandbox와 다르다.

`plan`/`code`와 child delegation은 persistent v2 run, PostgreSQL checkpointer, 명시적 root `agent_budget` 및 operator project quota를 요구한다. Code root와 모든 child는 MariaDB sandbox intent와 함께 `waiting_resource`로 시작하고, controller가 cloud observation·bootstrap 인증서·sandbox readiness를 확인한 뒤 `queued`로 옮긴다. API는 선택한 plugin wheel set digest를 run에 고정하고 worker는 새 claim에서 registration boot/resource generation·fingerprint, protocol, digest 및 readiness를 검증한다. Worker는 `owner#lease_fence` 토큰으로 claim하며 controller는 live lease·worker certificate·resource generation을 확인해 15초 이내의 per-call capability를 발급한다. Guest HTTPS는 같은 TLS socket에서 peer pin/SAN 확인 뒤 source/bearer를 보낸다. 이미 발급된 capability는 DB lease revoke 후 만료 전까지 사용 가능한 창이 남는다. `run_code`는 별도 internal mTLS 경로만 사용하고 artifact를 worker가 pull/ingest하며 public SSRF policy는 유지한다.

`delegate_agent`는 승인된 같은 owner agent, frozen parent authority와 budget의 부분집합만 고른다. 한 model response의 child calls는 한 MariaDB wait group/ordinal로 저장되고 parent는 checkpoint-compatible children interrupt 후 `waiting_children`로 내려간다. Child completion은 결과·reservation 정산·join marker를 기록하고 DB scan/Redis wakeup으로 parent를 재개한다. Replay는 기존 group/call identity를 재사용하며 cancel은 descendant를 terminal cleanup으로 보낸다. Nova create의 lost response는 unknown intent로 유지해 중복 생성·임의 삭제를 금지한다. Zun은 adapter 코드가 있지만 sandbox host isolation 강제가 없어서 pool config가 모든 Zun 역할을 거부한다. 외부 OpenStack 제공자의 안전성/격리는 cloud 검증 전까지 입증되지 않는다.

### Active-path history and branches

`chat_message_graphs(id,user_id,project_id)` owns encrypted immutable message bodies; `chat_conversations.graph_id` is an independently titled mapping with a selected leaf, `history_revision` and `chat_conversation_active_path(conversation_id,position,message_id)`. `chat_messages.graph_id` fixes ownership; `conversation_id` is nullable creation provenance only. `chat_conversation_messages` explicitly grants reachability to a conversation, including inherited ancestor IDs; a shared graph alone does not authorize a sibling branch. Writers and readers require conversation user/project plus graph owner, matching message graph and membership; changing an ancestor shared with a fork is refused. Fork creates mapping/membership/projection rows without copying message bodies, ciphertext or asset links; source deletion does not break a fork, and the final mapping deletion atomically removes graph, messages and message-asset links. Origin run/usage audit follows its existing retention/SET NULL rules.

`lumen-migrate --apply` applies additive migration 019 to each legacy conversation as its own graph; already copied forks are never content-deduplicated. It discovers the actual old origin FK name/collation, backfills graph IDs and all legacy origin memberships, checks owner/graph integrity before NOT NULL/FK/index DDL, projects any unready histories, and verifies contiguous/root-to-leaf/terminal/membership paths before recording the migration ledger. Partial DDL is resumable and a second application is inert. Stop writers, back up MariaDB and coordinate API/worker cutover; a mixed old/new deployment is unsafe.

The hot page path reads indexed active-path positions from the selected leaf backwards for `anchor=latest` or an exclusive before cursor, then reverses the bounded page into display order. A revision mismatch returns 409; malformed or cross-conversation opaque cursors return 422. `ChatMessage.conversation_id` is never used to authorize inherited messages, and `_msg_public` reports the requested view conversation. Inherited user messages cannot expose the source run as fork-local retry; title jobs snapshot the reachable first exchange under the selected conversation lock, with manual title revision CAS fencing later results.

### Worker recovery and background work

`lumen/worker.py`는 capacity만큼 active task를 유지하면서 빈 slot을 즉시 채우고 독립 maintenance task로 stale run recovery, pending input/approval expiry, temporary thread purge, title/memory/background workspace jobs를 처리한다. Managed worker 등록은 bootstrap-issued generation/certificate fingerprint와 plugin digest를 DB에 고정한다. 새 claim은 현재 resource readiness·protocol·plugin digest·20초 이내 heartbeat·accepting을 검증하고, SIGTERM drain은 새 claim을 막지만 유효한 기존 lease의 capability를 허용한다. API guest의 독립 mTLS `/v1/ready`는 public process의 DB/plugin/checkpointer와 loopback-only active/SSE count·streaming 첫 text p95를 보고한다. Controller는 probe 실패 시 ingress를 disable하고 freshness 없는 telemetry로 scale-down하지 않는다. Redis wakeup은 최적화이고 MariaDB queued state·lease·journal이 복구 기준이다.

Title recovery reuses the durable first-title job rather than doing model work in a GET. Once per idle minute it selects an active, titleless `auto/idle/revision=0` conversation with a completed persistent root exchange and no title job; empty conversations cannot starve later candidates. The selected mapping's reachable first user/assistant exchange (including inherited user IDs) is snapshotted into its title job under its lock. Unusable route/source candidates become `unavailable`. Manual updates atomically mark the title explicit/ready and advance its revision; late title results fail the revision CAS. Legacy/manual/failed/deleted rows and ambiguous provider calls are not replayed.

The title call (`lumen/services/title_summary.py`) sends a reasoning effort only when the frozen route's `capabilities.reasoning_options` advertises an `effort` list. It picks the cheapest listed value in the order `none → minimal → low → medium → high → xhigh → max`, so gpt-5 gets `minimal`, o3 gets `low`, gpt-5.1 gets `none`, and claude-opus-5-5 gets `low`. Routes with only `budget_tokens`/`toggle` options, empty options (LiteLLM/ChatGPT fallback capabilities), `reasoning=false`, or no capabilities omit the effort and keep the provider default. `_reasoning_params` preserves advertised `none` even when the provider catalogue probe is stale; other chosen efforts still require the provider probe. Options enter the real `acompletion` wrapper through `extra`, not unsupported top-level keywords. Integrated-tree contract 1,369 and MariaDB integration 70 passed (2026-09-27), including fork first-title snapshot and manual revision fence; this does not prove a live title-model response, storage on production, or sidebar rendering against production. No service, store, or ownership boundary is added by the title parameter change.

Context capacity resolves exact catalog input windows, including the stored Perplexity route alias, while explicit reviewed overrides retain precedence. Unknown limits, uncountable input and invalid budgets have distinct reason codes and never project a fabricated percentage. Text counter failure retains a labeled estimate. Both manual compaction endpoints return the actual unavailable reason. Agent search-result events/output items (including `response.output_item.added`) survive LiteLLM's empty-chunk filtering through provider-specific delta metadata, then join URL annotations in the canonical citation projection without losing inline ranges. A failed tool-schema validation is persisted and emitted with failed tool status rather than being projected as a completed task. These changes add no service, database schema or ownership boundary.

Provider-native compaction layers under, not over, that fence. `native_compaction.py` resolves an Anthropic `context_management` edit at the same 0.80 occupancy ratio, but the provider trigger is an absolute input-token count against the raw window while the Lumen fence divides by `input_budget`, so the Lumen fence always trips first and stays the durable, provider-neutral mechanism. The edit is armed only where the pinned LiteLLM chat transport forwards `context_management` — Anthropic today; every other route resolves to `None` rather than sending a parameter `drop_params` would silently discard. A window that cannot express the ratio above the documented 50,000-token floor is left unarmed rather than clamped to a trigger that can never fire. `chat_native_compaction_enabled` disables it without touching Lumen's own compaction. Returned `compaction` blocks are carried on every later assistant turn of the run, including replayed turns, because a dropped block makes the provider re-compact and re-bill the same prefix; blocks are bounded and re-validated before they are sent back. On the Anthropic passthrough surface the per-iteration `usage.iterations` breakdown now drives billing, since the top-level counters exclude the compaction iteration entirely. Compaction blocks are carried within a run, not across conversation turns — cross-turn continuity remains Lumen's encrypted summary checkpoint. This adds no service, database schema or ownership boundary.

The stateless compatibility proxies (`/v1/messages`, `/v1/responses`, and the Claude gateway) carry no durable run, so Lumen's own fence never sees them and the provider's compaction is the only thing between a long client session and a hard context-length error. `complete_anthropic` and `complete_responses` therefore supply a resolved `context_management` value when — and only when — the caller sent none; a caller that sent its own configuration keeps it untouched, because overriding it would silently change a compatibility client's contract. The two protocols share neither a wire shape nor a floor: Anthropic takes `{"edits": [...]}` with a 50,000-token minimum while the Responses API takes `[{"type": "compaction", "compact_threshold": N}]` with a 1,000-token minimum, so they are resolved separately instead of being translated at the transport. `chat_native_compaction_passthrough_enabled` gates the proxies independently of the chat path because their blast radius differs: a proxy client that does not replay the compaction block pays for a fresh compaction each turn rather than reusing the previous one.

Built-in remote MCP connector bundles (`mcp_bundles.py`) are declarative presets for `scope="global"` rows in `chat_mcp_servers`: Notion and GitHub, both `auth_mode="oauth"` and `load_policy="on_demand"`. Neither product is an Anthropic-executed server tool, so the MCP connector path is the only mechanism; the bundles therefore reuse the existing per-user PKCE OAuth flow and carry no credential material of their own. Installation is additive and idempotent by destination because rewriting a shared global row bumps `config_version` and revokes every user's connection to it. Because an active global row is implicitly selected for every user, admission now excludes an OAuth connector with no usable connection from an *implicit* selection instead of freezing it and having the worker reject it with a credential warning on every run; an explicitly selected or agent-allowlisted connector still surfaces that warning.

`ContextState.breakdown`은 preview와 request scope에서 메시지·system prompt·workspace·memory·skills·agent·summary·attachment·function/MCP schema와 framing의 안전한 이름, 개수, token measurement를 제공한다. `context_inspector.py`는 실제 카운팅 입력의 marginal 비용을 배분하며 complete이면 included component 합계가 `input_tokens`와 같다. Shared custom-tool schema builder가 admission과 runtime schema 차이를 방지한다. On-demand 도구는 deferred로 분리하고, 아직 발견하지 못한 MCP schema나 읽지 못한 attachment는 uncounted로 표시하여 거짓 잔여 비율을 막는다. 실제 노출된 도구는 모든 내부 identity를 비교해 deferred에서 제거하며 공개 이름 목록만 bounded 처리한다. 모델 입력 한도가 unknown이어도 구성 이름과 개수를 유지하고, 기존 journal에는 optional breakdown의 부재를 허용한다.

## Data and contracts

- **Authoritative MariaDB**: provider/model catalog, owner/project-bound `chat_message_graphs`, immutable encrypted `chat_messages`, per-conversation explicit `chat_conversation_messages` reachability, separately owned `chat_conversation_active_path` projection/revision/title, run/event/turn/segment/lease journal, ordinary/expiring legacy-device API-key hash·scope·owner/admin 한도, hashed one-time custom device grants, quota policy/wallet, encrypted provider credentials, extension/skill/memory metadata와 immutable usage ledger가 정본이다. Indexed projection은 normal read path이고 graph parent는 audit/branch operation을 보존한다. A nullable origin conversation ID is provenance, never an authorization predicate. Secret-bearing content crosses the encryption boundary; do not copy ciphertext or raw secrets into response.
- **Agent-platform migrations 015/016**: `chat_plugin_bindings`는 owner/global export·암호화 config·version의 정본이고 `chat_runtime_*`, `chat_worker_registrations`, `chat_agent_reservations`, `chat_delegation_*`는 quota/resource generation/child join의 정본이다. `chat_runs.lease_fence`는 stale worker를 차단한다. Controller와 worker는 같은 MariaDB schema/image/plugin 버전을 사용해야 하며 migration checksum은 manifest와 일치해야 한다.
- **Redis cache/queue/rate-limit roles**: cache와 일반 run wakeup은 유실되어도 MariaDB 정합성을 바꾸지 않고 worker가 DB polling한다. Legacy device brute-force/poll limiter와 realtime 60초 one-use WS ticket는 보안 경계이므로 Redis 장애 시 해당 operation만 fail-closed 503이다. Realtime run은 API socket이 직접 lease를 claim하므로 worker queued polling에서 제외된다.
- **PostgreSQL boundary**: configured encrypted LangGraph checkpointer는 protocol v2 admission prerequisite이며, `CHAT_MEMORY_PGVECTOR_URL`은 선택 semantic-memory index다. PostgreSQL은 MariaDB run/event/catalog의 대체 정본이 아니다. semantic ranking과 recency prompt hydration도 별도 경로다.
- **Other stores**: configured S3는 service-owned asset object store이고 finite image/TTS/STT media에는 scanner와 함께 필수다. Realtime audio는 S3에 기록하지 않는다. Asset metadata/ownership은 MariaDB가 보유한다. ClamAV/sandbox/MCP는 해당 기능의 외부 boundary다.
- **Internal sandbox boundary**: sandbox의 per-call SQLite journal은 같은 resource의 idempotent local result만 보존하고 LangGraph checkpoint/Redis와 마찬가지로 Lumen의 run/event 정본을 대체하지 않는다. Operator cloud credential과 dispatch key는 controller 전용; worker에는 발급된 client identity만, sandbox에는 해당 resource/run/generation의 파생 key만 들어간다. Public custom HTTP/MCP SSRF restriction은 내부 private transport에 적용되지 않으며 서로 공유하지 않는다.
- **Organization usage windows**: OpenAI/Anthropic 조회는 UTC 월 시작과 현재 주 월요일 중 이른 시각부터 가져온 뒤 일·주·월로 따로 집계한다. 월초에도 전월에 속한 이번 주 사용량을 누락하지 않으며 31개 daily bucket 범위를 유지한다. Route·credential·schema 경계는 변경하지 않는다.
- **Package dependency boundary**: root `lumen` distribution has no base runtime dependency and ships Kolla role files as wheel shared data. Service code, service CLI, and root tests require the explicit `service` extra; development adds `dev`. Kolla-Ansible remains an operator-owned dependency, not a Lumen package dependency.
- **Media accounting/privacy**: migration 020의 media model kind/prices는 token price와 독립이다. Image/audio provider segments는 worker, realtime provider segment는 API WS가 소유한다. `ChatModelCallReservation`의 `reserved|unknown` bound를 wallet lock 아래 사용자·API-key 월/주 한도에 포함하고, 실제 이미지 단위/PCM 초가 확인될 때 ledger와 hold를 같은 transaction에서 정산한다. Realtime raw PCM/transcript는 provider로 relay하지만 MariaDB/S3에는 저장하지 않는다. Provider 결과가 불확실한 hold는 자동으로 release하지 않는다.

- **API contracts**: native `/v1`은 run descriptor, UUID idempotency, active-path cursor, owner-scoped run/event, replay cursor와 terminal event를 계약으로 한다. Text compat의 OpenAI Chat Completions/Responses와 Anthropic Messages/count_tokens는 stateless지만 image/audio/realtime compat는 별도 durable media run/usage를 생성한다. Discovery의 `clients.claude_code`는 ordinary-key direct Anthropic base를 가리킨다. Legacy Lumen device surface는 custom OAuth grant와 24시간 fixed-scope credential이며 current Claude Apps Gateway compatibility를 주장하지 않는다. discovery/API contract version은 `1.0.0`; root package `0.4.0`와 SDK `0.2.1`은 별개 release value다.
- **SDK transports**: `lumen_sdk.Client`와 OpenStack SDK `Proxy`는 opaque history cursor를 변환하지 않고 같은 native page contract를 전달한다. 이 둘은 Lumen API transport이며 provider credential transport가 아니다.
- **Protocol invariant**: accepted durable run에는 admission snapshot, pricing/provenance, selected extension/config fingerprint가 있어야 하며 worker가 mutable configuration을 재검증한다. `model="lumen"` bridge는 tools/memory가 없는 text-only 입력만 accepted한다. Compat provider request는 Lumen conversation/active-path에 저장되지 않는다.
- **Release snapshot compatibility**: Migration 020의 기존 text model `model_kind=text`·`media_pricing=NULL`은 v0.3.1의 route HMAC 직렬화에 추가하지 않는다. 정지 시 남은 queued text run은 설정이 실제로 바뀌지 않았다면 기존 frozen hash로 재개하며, 이미지·오디오·realtime route는 kind와 media 가격을 hash에 포함해 변경을 차단한다. 고정된 v0.3.1 HMAC/실제 ORM 조회 회귀가 이 경계를 검증한다.
- **0.3.1 integration boundary**: `origin/dev`의 title/admission/operator/graph reasoning 수정과 기존 subscription sampling·operations 변경을 별도 worktree에서 통합했다. Legacy Perplexity Sonar의 정확한 bundled 가격 키를 synthetic Agent 중복 접두보다 우선해 서로 다른 tariff를 유지한다. Managed runtime guest 인증서의 Authority Key Identifier는 controller CA의 Subject Key Identifier가 있으면 그 값을 사용하고, 없으면 CA 공개키에서 유도한다. 기존 CA material·소유권은 변경하지 않는다. 서비스·schema·dependency·저장소 소유권 변경은 없으며 root/runtime/lock 및 packaged Kolla image default만 patch version으로 맞춘다. 기존 discovery는 변경하지 않았다. 0.3.1 candidate에서 contract 1,369건, SDK 125건, 실제 MariaDB/Redis integration 40건, local Compose fake-provider system 9건, Ruff와 wheel build, API/worker/controller/sandbox linux/amd64·linux/arm64 이미지 build 및 각 이미지의 offline import/platform smoke를 통과했다. `v0.3.1` package/image workflows와 네 tag image의 linux/amd64·linux/arm64 manifest/OCI revision은 게시 후 확인했다. live Anthropic/OpenAI provider·production rollout은 아직 검증하지 않았다.

### Provider model onboarding

관리자 discovery는 Anthropic `x-api-key`/`anthropic-version` + `after_id`, Gemini `x-goog-api-key` + `pageToken`, OpenAI-compatible Bearer `/models`로 계정별 후보를 조회한다. 기존 Perplexity router·custom base와 subscription namespace를 보존한다. HTTP client는 redirects/environment proxy를 사용하지 않고 전체 20초·25페이지·2,000 unique 모델·5MB streamed identity response로 제한한다. 정상 empty는 complete API 결과다. 오류나 중간 페이지 실패·한도 초과는 모델 목록 전체를 폐기하고 safe error로 반환하며 static fallback을 하지 않는다. Static 참고 목록은 live 미지원 provider/auth에만 제공한다.

`available-models`는 no-store와 `provider_id`, `fetched_at`, `source`, `live_status`, `complete`, `error`, `models`, `candidates`를 반환한다. Upstream 401/403은 caller session 오류와 구별되는 HTTP 200 structured discovery error다. 후보의 exact opaque ID·표시명·generation methods·token limits는 등록/가격/고급 기능/실제 추론 증거가 아니다. 신규 ID는 기존 CRUD와 request-time DB route를 사용하며 native admission은 가격 쌍과 별도 feature gate를 검사한다. LiteLLM 계산기가 unknown ID에 0을 반환해도 exact catalog entry의 명시 단가 없이는 free 가격으로 인정하지 않는다. 명시적 0 USD와 미확인 `null`을 구분한다.

`OPENAI_API_KEY`/`GEMINI_API_KEY`가 bootstrap process에 있으면 공식 direct `openai`/`gemini` provider를 자동 등록한다. DB는 key 값이 아닌 `api_key_env` 변수 이름만 갖는다. Existing DB key, admin env binding, custom base, margin, active flag는 bootstrap이 바꾸지 않으며 빈 키를 새 provider로 등록하지 않는다. `LUMEN_BOOTSTRAP_MODELS_JSON`은 관리자가 지원 모델의 단위 가격을 명시할 때만 새 model을 만든다. Media는 kind/variant/초당·분당 rate의 형식과 지원 transport를 검증하지만 공식 제공사 가격의 정확성까지 확인하지는 않는다. 키만으로 media capability·가격·모델을 생성하지 않으며 로컬 기본 text 모델은 별도 seed한다. 이미지/음성/Live 실증은 별도다.

## Deployment and operations

로컬 Compose(`docker-compose.yml`)는 MariaDB, Redis, migration/backfill, idempotent `seed-local`(공통 env provider bootstrap + text 모델 + scoped key), API, worker, opt-in connection helper와 localhost Console을 분리한다. API 기본은 `127.0.0.1:8012`다. `OPENAI_API_KEY`/`GEMINI_API_KEY`는 seed/API/worker에만 전달되고 `.env`는 Git과 Docker build context에서 제외한다. Provider key 없이 stack은 기동해도 completion은 실행되지 않는다. `lumen-migrate --apply`가 기존 projection/Gateway/cache/media migrations를 완료한 뒤 bootstrap이 실행되고 API/worker가 시작된다. Gateway local base는 loopback HTTP를 허용하지만 model/provider route가 없으면 inference는 503이다.

Migration 012의 active-path table은 기존 FK parent와 같은 database collation을 상속하도록 explicit charset/collation을 지정하지 않는다. MariaDB DDL autocommit 뒤 재실행해도 안전하도록 table, column, index 생성은 `IF NOT EXISTS`를 사용하며 integration datastore는 `utf8mb4_unicode_ci` database에서 이 계약을 검증한다.

Service 이미지는 root `service` extra의 workspace plugin distributions와 editable source 경로를 함께 보존한다. `docker/Dockerfile`은 workspace manifests를 먼저 복사하고 `uv sync --locked`로 manifest/lock 불일치를 build 단계에서 거부한다. 최종 API/worker/controller 공통 runtime은 `packages/lumen-plugin-api`와 `plugins/`를 포함하고 non-root 사용자로 실제 `python -m lumen.scripts.migrate --help`를 실행해 import 누락을 검출한다. 이 검사는 DB에 연결하거나 migration을 적용하지 않는다. Sandbox는 이 trusted runtime과 별도 stage이며 service workspace에 포함하지 않는다.

Kolla role은 API/worker를 별도 host-network container로 실행하고 MariaDB/Valkey, Keystone, encryption key, PostgreSQL mode와 `claude_gateway_base_url/model/provider`, Afterglow `frontend_base_url`을 주입한다. Vault-protected inventory `lumen_openai_api_key`, `lumen_gemini_api_key`, optional `lumen_bootstrap_models_json`은 migration 뒤 no_log one-shot CLI와 API/worker env에만 전달된다. Non-loopback Gateway base는 HTTPS와 exact `/v1/claude-gateway` path가 필수다. `deploy`, `upgrade`, `reconfigure` bootstrap은 migration/backfill→provider registration을 API/worker start 전에 실행한다. 현재 source-build pin `c561a155...`는 CLI보다 오래되었으므로 변경된 source/image로 operator가 pin을 갱신하기 전 Kolla 배포를 완료했다고 주장하지 않는다.

`GET /v1/health`와 Kolla healthcheck는 process HTTP response만 확인한다. Migration checksum/projection integrity, DB/Redis, worker, Gateway device login, provider inference readiness는 별도 검증한다. 운영 장애 시 journal, lease, provider snapshot, migration ledger/checksum, unready history count와 Gateway OAuth safe code를 함께 확인한다. Backup은 active-path/device/API-key metadata를 포함한 MariaDB, configured PostgreSQL, S3와 encryption key recovery를 일관되게 계획한다.

## Security boundaries

- **Principal**: Keystone token, scoped ordinary API key와 expiring legacy-device API key를 `Principal`로 정규화한다. 한 요청에 여러 credential을 보내면 400이다. 동일한 API key를 `X-API-Key`와 `Authorization: Bearer`로 중복 전달한 경우만 값이 일치할 때 허용하며(Claude Code 기본 동작), API key는 project에 고정된다. Custom gateway route는 `credential_kind="claude_gateway"`와 fixed scope를 추가 검사하며 ordinary key를 거부한다. Keystone만 management/approval route를 사용한다.
- **Authentication I/O scheduling**: async Keystone dependency는 동기 validation을 bounded Starlette thread pool에서 기다린다. Token rescope/target project/admin 판정은 유지하며 cache/fail-open을 추가하지 않는다.
- **Target project**: Keystone connection project와 logical target project를 분리하며 다른 target은 검증된 system admin만 지정할 수 있다. Gateway approval은 현재 authenticated user/project에 grant를 묶는다.
- **Secrets**: encryption key는 64 hex이며 domain separation으로 chat/provider/billing/extension content를 분리한다. Ordinary/Gateway API key와 device/user code는 hash만 저장하고 plaintext credential은 successful issuance response에서 한 번만 노출한다. Raw credential/provider/MCP/Git/S3/tool secret은 log/journal/response에 기록하지 않는다.
- **Kolla managed-runtime identity**: controller만 root-owned 서명 키·CA private key를 읽기 위해 컨테이너 root로 기동하며 Docker socket을 받지 않는다. Stock worker에는 별도 제한된 디렉터리의 public CA·client cert/key 세 파일만 group-readable read-only로 마운트하고, 동일한 container TLS 경로에서 operator key나 CA private key를 노출하지 않는다. Precheck가 파일 위치·소유권·모드·허용된 세 파일만 검증하며 Kolla TOML의 runtime JSON은 문자열로 escape한 뒤 설정 loader가 typed object로 복원한다. Source mode는 controller target도 빌드한다. Compose의 수동 controller profile은 격리/cloud acceptance가 아니다.
- **Network**: custom HTTP/MCP 경계의 SSRF/TLS 정책을 유지한다. Gateway public base는 non-loopback HTTPS만 허용하고 host gate를 적용한다. Device issuance/approval rate limiting은 Redis failure를 503으로 거부한다.
- **Execution trust**: durable admission은 immutable snapshot을 저장하고 worker가 route/credential generation을 재검증한다. Compat/Gateway stream disconnect는 provider read를 cancel하지 않는다. API/Gateway key revoke/expiry는 새 request를 막지만 이미 accepted durable run은 snapshot 계약을 따른다.
- **Console**: local Console SQLite는 local password hash/session hash만 저장하고 Lumen API key/Keystone token을 저장하지 않는다. seed volume과 one-shot connection output은 local development secret boundary이며 repository/CI log에 기록하지 않는다.

## Maintenance

Architecture is a living snapshot, not a historical plan. 작업 전 이 파일을 읽고, code/config/schema/dependency/deploy/test 변경이 있으면 영향받는 본문과 해당 상세 문서를 같은 변경에서 갱신한다. 구조 영향이 없는 bugfix/refactor도 최신 review summary에 영향 없음의 근거를 남긴다. 실제 source와 tests를 읽은 뒤 architecture guard를 stamp하고, 완료/commit 전 working 또는 staged check를 통과시킨다. 문서와 source가 어긋나면 source가 정본이며 문서를 현재 구현에 맞춘다. 다른 checkout의 private module import나 새 network dependency를 문서 계약으로 만들지 않는다.

권장 순서:

1. 이 root 문서와 영향받는 detail docs를 읽는다.
2. source/config/schema/dependency/deploy/test의 실제 callsite와 현재 한계를 확인한다.
3. 본문·code map·status·change guide와 필요한 detail docs를 함께 수정하고, test-defined와 실제 실행된 evidence를 구분한다.
4. guard가 제공된 뒤 `python3 scripts/check_architecture.py`를 실행해 source snapshot을 확인한다. staged 제출 범위만 검토할 때는 `python3 scripts/check_architecture.py --staged`를 사용한다.
5. 변경 설명과 최신 review marker를 남기고 pre-commit/CI의 `architecture` hook을 통과시킨다. marker의 digest/timestamp/summary는 실제 stamp 결과만 사용한다.

## Glossary

- **Admission**: 요청 권한·context·provider·extension·pricing을 계산해 immutable run snapshot과 MariaDB transaction을 만드는 단계.
- **BFF**: Afterglow Backend-for-Frontend. Lumen 내부 실행을 소유하지 않고 인증된 browser request를 Lumen `/v1`로 forwarding한다.
- **Durable run**: API/SSE 연결과 독립적으로 MariaDB journal, lease, worker execution으로 진행되는 실행 단위.
- **Journal**: `ChatRunEvent` sequence와 terminal state를 포함하는 authoritative run/event 기록.
- **Lease**: 한 worker owner만 run을 갱신하도록 하는 만료 가능한 실행 소유권.
- **Snapshot**: admission 시점 provider/model/feature/extension/context/pricing identity를 freeze한 값.
- **Stateless completion**: provider model ID를 직접 LiteLLM으로 호출하고 HTTP 요청의 응답으로 끝나는 compat 경로.
- **Virtual model `lumen`**: OpenAI compat에서만 제공되는 durable bridge 식별자. text-only native-like worker execution을 뜻한다.
- **MCP**: Model Context Protocol remote server/tool 경계. Lumen은 owner-scoped selection과 Afterglow control-plane authority를 재검증한다.
- **Checkpointer/pgvector**: 각각 protocol-v2 LangGraph state checkpoint와 선택 semantic-memory index를 위한 PostgreSQL 경계.
- **Console**: Afterglow UI가 아닌 local developer/operator tooling. Lumen API 인증·scope·durable admission을 우회하지 않는다.
