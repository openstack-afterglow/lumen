# Changelog

## Unreleased

- Public model provider selectors now use the registered provider name (including names such as `nvidia nim`), separately from internal LiteLLM `provider_type`. Multiple registrations sharing one model ID require an explicit name; renaming a provider changes its public selector and rejects empty names. Claude Gateway `claude_gateway_provider` also selects that registered name (up to 100 characters); operators must update a former transport-type value or renamed provider before Gateway requests resume. The Kolla TOML template escapes names containing quotes or Unicode.
- Additive migration `020_global_model_order.sql` and atomic `PUT /v1/admin/models/order` persist one global model sequence shared by admin, chat, and OpenAI discovery. Apply the migration before matching API/worker startup; order-only changes do not alter price versions.
- Missing cache-write rates now resolve 5m from input and 1h from 5m after manual/direct catalog rates, preserving explicit zero and distinct Anthropic 1h prices. Effective admin cache fields remain separate from nullable stored manual rates. New executor/advisor/title admissions freeze resolved prices; historical snapshots remain unchanged and missing cache-read is still unpriced. Local calculator smoke, service contract (1390), SDK (125), Ruff, MariaDB/Redis integration (71, including migration 020) and local API/worker Compose fake-provider system (9) passed; external provider billing and rollout remain unverified.
- Native conversations now share an owner-scoped immutable message graph on new forks. Each fork owns title, active path, revision and explicit ancestor memberships; unchanged encrypted message/asset data is no longer copied. Removing a source preserves surviving forks; removing the last view collects the graph. Latest-first cursor pages, durable run replay, inherited title exchange and owner/project isolation retain their native API contracts.
- Additive migration `019_shared_message_membership.sql` and a resumable integrity/backfill guard require a **stopped-writer, backed-up** MariaDB cutover before starting matching API/worker images. Old writers cannot run against this schema and downgrade requires restoring the pre-cutover database and old images together. Isolated MariaDB migration (twice), complete 70-test integration layer and direct graph lifecycle smoke passed; public provider inference and production rollout remain unverified.

## 0.3.1 (development release candidate)

Changes since `v0.3.0`:

- **Title reasoning:** Select only the cheapest effort advertised by the frozen route and pass it through the completion wrapper's `extra` options, avoiding an unsupported keyword error. Missing, budget-only or toggle-only metadata keeps the provider default. Regression cases exercise the real wrapper at the LiteLLM boundary.
- **Graph reasoning:** Implicit GPT-5 tool-round `none` requires the frozen route's disable capability; provider rejections are remembered before the durable failure boundary aborts the run. All reasoning memos are scoped to the frozen provider/model configuration hash, not a shared model name. Calls without a frozen identity do not reuse process-wide guesses.
- **Subscription sampling:** Anthropic subscription calls enable the same unsupported-parameter dropping as API-key calls. A deterministic installed-mapper regression covers the Opus sampling constraint; operations guidance retains native compatibility passthrough limits.
- **Explicit disable intent:** A validated/advertised `none` survives a stale LiteLLM reasoning probe and generic graph fallback; rejection is not silently retried with provider-default reasoning. Deterministic regressions cover different routes/versions, absent route identity and title transport.
- **Opaque OpenAI routes:** Explicit `none` is allowlisted through LiteLLM's installed parameter mapper even with `drop_params=True`; the override is limited to that option on OpenAI wire, leaving native Anthropic/Gemini mappings unchanged. The transport regression inspects mapped provider options, not only mocked completion arguments.
- **Perplexity legacy tariff identity:** An exact `perplexity/sonar` catalog entry wins over the synthetic double-prefixed Agent identity when resolving legacy API prices. Agent Sonar still uses its independent published Agent tariff; unknown Agent prices remain unpriced.
- **Managed runtime mTLS:** Issued sandbox/API/worker certificates include an Authority Key Identifier matching the signing CA's Subject Key Identifier, including CAs with a non-derived key identifier; CAs without that extension retain the public-key-derived identifier. The deterministic pin/SAN transport test CA and leaf certificates carry strict-X.509-required key identifiers and usages, so current OpenSSL verification reaches the authenticated transport rather than failing the handshake.
- **Reasoning `none` admission:** An explicit `reasoning_effort="none"` now returns 422 unless the model advertises disabling reasoning (models.dev effort list with `none`, a `toggle`, `budget_tokens` minimum 0, or an Anthropic provider). Previously it was forwarded to models such as gpt-5, o3 and gemini-2.5-pro that reject it. `GET /v1/chat/models` adds `reasoning_none_supported` for clients. models.dev imports now keep `budget_tokens` `min`/`max`; models imported earlier reject `none` until re-imported. An operator `chat_reasoning_effort="none"` default is omitted for such models instead of being sent.

**Release boundaries:** Root manifest, runtime version, lock entry and packaged Kolla API/worker/controller defaults target `0.3.1`. SDK `0.2.1`, plugin API/default plugins `0.1.0`, sandbox distribution and source-build commit pin remain independent. This is a release candidate, not a published tag or image. Local contract (1,369), SDK (125), datastore integration (40), Compose fake-provider system (9), Ruff and installed wheel checks passed; API/worker/controller/sandbox images were built and executed on linux/amd64 and linux/arm64. Cloud rollout and tag workflows remain pending. Existing discovery is unchanged; real Anthropic/OpenAI inventory, approved paid native/compat inference and usage acceptance remain open in OpenSpec and must not be inferred from synthetic evidence.

## 0.3.0 (release candidate)

Changes since `v0.2.1`:

- **Live model discovery and onboarding:** Admin discovery reads bounded, credential-scoped Anthropic, OpenAI-compatible and Gemini model inventories with source/status, safe errors and no partial-list fallback. Previously unknown model IDs can be registered with explicit prices and routed through native and compatibility calls without a worker restart. Discovery does not establish prices, advanced capabilities or successful upstream inference.
- **Agent and plugin platform:** Separate plugin API and five default plugin wheels provide operator-approved bindings for database, memory, tools, skills and MCP. Durable child runs, budget and cancellation accounting, resource intents and fenced controller/worker registrations support managed sandbox execution. The sandbox remains a separate distribution and image; Zun pools are rejected where isolation is not enforced.
- **Authentication and protocols:** OpenAI Responses and Anthropic Messages compatibility, current Claude Code ordinary-key transport and the legacy Lumen device grant, active-path history with revision-fenced cursors, provider-native compaction and built-in MCP connector bundles landed. The custom device grant is not the current Claude Apps Gateway protocol. Prompt-cache usage and pricing are accounted for by model and cache tier; invoice reconciliation remains outstanding.
- **Packaging and CI:** The root `lumen` wheel now carries the Kolla role as shared data. The service-extra/workspace packaging includes the plugin wheels; multi-architecture API, worker, controller, test and sandbox images have been built and exercised on both target architectures. CI uses one reusable test workflow for branch push/PR, guarded PR deduplication, pinned uv image digest and branch-only BuildKit cache exports. Tag pushes still invoke the reusable tests twice, through both package release and image publishing workflows.

**Release boundaries:** The root package and Kolla API/worker/controller image default target `0.3.0`; the image tag is not a published-image claim until the `v0.3.0` workflows succeed. SDK `0.2.1`, plugin API/default plugins `0.1.0` and the standalone sandbox version remain independently versioned; the Kolla source-build commit pin remains separate. Synthetic-provider and local Compose evidence must not be promoted to real Anthropic/OpenAI discovery or inference, native amd64 sandbox isolation, cloud sandbox lifecycle, Nova/Octavia deployment or GitHub tag-workflow acceptance. Live-provider onboarding and CI post-push follow-ups remain open in OpenSpec.
