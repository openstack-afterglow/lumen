## 0.6.5 — 2026-10-07

Changes since published stable `v0.6.3` (`cadb6ac`). This release includes the unpublished 0.6.4 Claude Code fix below and adds the following.

**Release boundary:** Root manifest/runtime/lock and packaged Kolla API/worker/controller image defaults target `0.6.5`. No new migration beyond 025 is introduced; published SQL and checksums stay immutable, and the 0.6.3 stopped-writer upgrade order still applies to deployments coming from ≤0.6.2. Batch and managed runtime remain disabled by default. The guest qcow2 workflow attaches artifacts to an existing release only after reviewer approval; no guest, cloud activation or production rollout is claimed by publication.

**Local qualification (2026-10-07):** On the merged release tree, the service contract passed 3,038 (312 deselected), SDK 128, root/SDK Ruff, disposable MariaDB/Redis integration 282 and canonical Compose system 30. Keystone and provider HTTP were synthetic in these layers, so they are not production RBAC, paid-provider, Nova/Octavia or rollout evidence.

- **Current scoped service authority:** Lumen validates exact unique global role IDs, the live Keystone inference DAG and enabled effective user/project grants; preset names and token role snapshots no longer stand in for capability authority. Ordinary keys attenuate current owner actions, require keys-editor plus the requested subset at issuance, and never inherit global administrator privilege. Inventory/history, config editing, destructive resources-admin, independent chat/image/audio/tools actions, automatic memory read, MCP and private-secret projections stay separate. Native/compat/provider/tool/worker boundaries fence only new external work; committed checkpoints and settlement survive downgrade without a second provider call. Owned image/audio/realtime cancellation needs its matching modality, not unrelated chat/history/delete rights, and remains idempotent. Built-in tools do not invent extension-inventory scope when no extension is selected. Local seed keys are bound to the real synthetic-directory owner and stale owner/scope keys rotate rather than bypass current authority. No migration, production role/DB mutation, paid-provider call or deployment.
- **Scoped-authority local evidence (2026-10-07):** Final frozen service contracts 3,005 passed (302 deselected, 21 dependency warnings), SDK 128 and root/SDK Ruff passed; canonical disposable MariaDB/Redis integration 272 and Compose system 30 passed, including 16 current-role HTTP/provider-count/worker/cancellation scenarios. Focused regressions passed 722 before the final built-in-tool scope correction; affected authority tests then passed 55 and the final full service gate passed. Initial contract/import lint and stale integration/system fixtures were corrected without weakening consumer assertions or widening seed/Gateway keys. Keystone/provider HTTP are synthetic; API/worker/journal/scanner/object-store are real local processes. This is not production, cloud-worker or paid-provider acceptance.
- **Bounded large Batch cancellation:** Cancel/expiry now freezes never-materialized items (no run, hold or result) in set-based pages of 5,000 inside the coordinator's batch lease, instead of 100 per one-second step. A real 50,000-row cancellation previously took 650s, beyond the 600s grace window. After the change it completed in 68.4s, including in-flight items, with output/error row counts matching settled holds and distinct ledger events. Regression failed before and passed after under MariaDB snapshot isolation ON/OFF; coordinator/file-GC integration 42 passed. Validation remains 100 rows per step: 50,000 rows took 617–635s before `in_progress`.
- **Guest artifact publication workflow:** Manual `nova-guest.yml` builds API/worker qcow2 on native amd64/arm64 runners only for an already published release from canonical `dev`/`main`. It requires the matching tag/commit, successful push or dispatch image/package CI, digest-equal version tags with matching revision labels, exactly pinned public build inputs and a reviewer-protected `nova-guest-build` environment that forbids self-review. The publish job re-verifies portable checksums, provenance, pins and `qemu-img check` before attaching without overwriting assets. Policy/tamper regressions and an actual `qemu-img` bundle verification passed. No guest was built, booted or published.
- **Bounded Batch validation authority:** Validation resolves the owner's current Keystone authority, attenuated by the API key, once per chunk of up to 100 rows and checks each row's required scopes against that set. Previously every row resolved authority separately, so one 50,000-row file could issue hundreds of thousands of directory requests. Row-level `api_key_unauthorized` errors, revoke handling during materialization and revalidation before each provider I/O are unchanged. Integration under snapshot isolation ON/OFF asserts one lookup for a 5-row chunk in both the authorized and denied cases. CI shape tests now cover every workflow and matrix runner, and a JSONL row-cap boundary test (2 accepted, 3 rejected) was added.

Changes since `v0.4.0`:

- **Explicit modality pricing:** Image-model discovery/registration and independent text/image/audio input, cached-input and output rates use the existing media JSON and text columns. Exact second/minute/hour, character, image-unit, whole-session and provider-token billing remain separate; omitted basis preserves legacy behavior. - **Timed native transcription:** Native `POST /v1/chat/audio/transcriptions` accepts optional `timestamp_granularities: ["segment"]`, only on executable direct OpenAI `whisper-1` (capabilities expose `available_timestamp_granularities`). Lumen sends `verbose_json` with `timestamp_granularities[]=segment`, keeps only validated provider start/end seconds and text, and returns `segments` with `text`; Lumen never infers timing. ## 0.3.1

Changes since `v0.3.0`:

- **Title reasoning:** Select only the cheapest effort advertised by the frozen route and pass it through the completion wrapper's `extra` options, avoiding an unsupported keyword error. Missing, budget-only or toggle-only metadata keeps the provider default. Regression cases exercise the real wrapper at the LiteLLM boundary.
- **Graph reasoning:** Implicit GPT-5 tool-round `none` requires the frozen route's disable capability; provider rejections are remembered before the durable failure boundary aborts the run. All reasoning memos are scoped to the frozen provider/model configuration hash, not a shared model name. Calls without a frozen identity do not reuse process-wide guesses.
- **Subscription sampling:** Anthropic subscription calls enable the same unsupported-parameter dropping as API-key calls. A deterministic installed-mapper regression covers the Opus sampling constraint; operations guidance retains native compatibility passthrough limits.
- **Explicit disable intent:** A validated/advertised `none` survives a stale LiteLLM reasoning probe and generic graph fallback; rejection is not silently retried with provider-default reasoning. Deterministic regressions cover different routes/versions, absent route identity and title transport.
- **Opaque OpenAI routes:** Explicit `none` is allowlisted through LiteLLM's installed parameter mapper even with `drop_params=True`; the override is limited to that option on OpenAI wire, leaving native Anthropic/Gemini mappings unchanged. The transport regression inspects mapped provider options, not only mocked completion arguments.
- **Perplexity legacy tariff identity:** An exact `perplexity/sonar` catalog entry wins over the synthetic double-prefixed Agent identity when resolving legacy API prices. Agent Sonar still uses its independent published Agent tariff; unknown Agent prices remain unpriced.
- **Managed runtime mTLS:** Issued sandbox/API/worker certificates include an Authority Key Identifier matching the signing CA's Subject Key Identifier, including CAs with a non-derived key identifier; CAs without that extension retain the public-key-derived identifier. The deterministic pin/SAN transport test CA and leaf certificates carry strict-X.509-required key identifiers and usages, so current OpenSSL verification reaches the authenticated transport rather than failing the handshake.
- **Reasoning `none` admission:** An explicit `reasoning_effort="none"` now returns 422 unless the model advertises disabling reasoning (models.dev effort list with `none`, a `toggle`, `budget_tokens` minimum 0, or an Anthropic provider). Previously it was forwarded to models such as gpt-5, o3 and gemini-2.5-pro that reject it. `GET /v1/chat/models` adds `reasoning_none_supported` for clients. models.dev imports now keep `budget_tokens` `min`/`max`; models imported earlier reject `none` until re-imported. An operator `chat_reasoning_effort="none"` default is omitted for such models instead of being sent.
