# OpenStack elastic runtime and dual Batch API

When usage grows, Lumen API and worker capacity moves from the fixed controller-node services to Nova guests on compute nodes. The change reuses the existing Nova resource controller, MariaDB durable journal and Octavia ingress. It also adds a native mixed multimodal Batch API and OpenAI-compatible Files/Batch. Both Batch contracts share one durable execution, cancellation and settlement ledger.

## Contract

- **Workload routing:** `ChatRun.workload_class` is `online_text|online_media|batch|realtime`. `worker_pool_id` and the claiming `worker_registration_id` are separate from sandbox `runtime_pool_id`. Candidate selection, claim and demand share one SQL predicate. Queued demand needs only a declared pool, so a min-0 batch pool can start from zero. Claims require a fresh, accepting registration and are limited by live leases. Fixed workers default to online text/media; batch runs only on a batch-only worker.
- **Admission and scaling:** HTTP, SSE and WebSocket slots are reserved before provider I/O or run admission and remain occupied through cleanup. Saturation returns 429 with `Retry-After: 1`; drain returns 503. Each pool reconciles from SQL demand, bounded service-time estimates, partial DB/PG budget clamps and replacement-only surge. Worker deletion requires a durable drain, an acknowledgement, zero live leases and zero auxiliary work. API deletion requires a private drain fence, applied Octavia weight zero with ACTIVE status, fresh zero counters and member removal before Nova removal. Unknown creates remain occupied and are not resubmitted.
- **Trusted guests:** Digest-pinned API/worker OCI images are preloaded into pinned Ubuntu 24.04 qcow2 guests. They never pull at boot. Guest configuration is delivered over mTLS from root-owned, hash-checked profiles that contain allowlisted keys and secrets only. Identity renewal uses current/pending/previous pins with replayable activation and keeps the unprivileged child running. The manual `nova-guest.yml` attaches guests only to an already published, CI-proven release after reviewer approval.
- **Batch:** The native API accepts six operations: chat, Responses, image generation/edit, TTS and STT. OpenAI-compatible Files/Batch support chat, Responses and image generation. Every item runs at most once through the existing durable run, hold and `run:<run_id>` ledger. Ambiguous provider I/O stays `unknown` with its hold. Cancel and expiry stop new I/O, freeze runless items in bounded set-based pages and give in-flight calls a 600-second grace period. Output files never change after publication. Batch is disabled by default.
- **Kolla:** A dynamic VIP switches both internal and public HAProxy backends to the validated Octavia member, using `/v1/ready` health and matching idle timeouts. Without that VIP, inventory backends remain. Precheck rejects placeholder or unsafe runtime material.

## Acceptance

Local acceptance covers contract, MariaDB/Redis integration under snapshot isolation ON/OFF, canonical system SDK workflows, worker-kill boundaries, 50,000-row load and cancellation, real HAProxy drain, guest TLS renewal, installed-wheel Kolla render with HAProxy syntax checks, and guest release policy. Promotion requires staging Nova/Octavia, real qcow2 builds and boots on both architectures, fault injection and paid-provider smoke. Production cutover needs separate approval.
